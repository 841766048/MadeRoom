# 导航修正 · 2026-09-28

## 已复现的根因

- navigate 对详情和表单只执行 push，重复搜索、重复目标和保存结果不断堆叠。
- 创建项目、保存空间、创建收藏集后，已提交的表单还留在 Back 路径。
- 完成作品加入空间仍停留在制作 Tab 的栈。
- 底栏按钮直接修改 selectedIndex，绕过制作空状态更新；返回根页还会切换到 Discover。
- 每页滚动内容中手写导航栏，没有统一处理侧滑与导航转场；底栏更新依赖布局时机。
- viewWillAppear 重建输入控件，临时打开相关页面后丢失未提交文本。

## 当前规则

1. 五个 Tab 各有独立 UINavigationController。切换保留栈，再次点击当前 Tab 回根页；显式跳转 Tab 首页也回根页。
2. 详情页使用固定的原生 UINavigationBar，支持返回按钮及屏幕左缘返回手势。根页保留品牌标题。
3. 同栈内已有目标返回该目标；不再重复 push 同一页面。转场期间拒绝额外 push。
4. 创建成功替换创建表单；编辑保存返回原详情；收藏集创建返回原列表。
5. 完成作品加入空间后进入 Spaces → 空间详情，Back 回空间列表；原制作流程的详情/完成页从来源栈移除。归档或删除项目也退出旧项目流程。
6. 根页不执行跨 Tab 的 Back。底栏只在根页显示，选中状态同步无障碍标识。
7. 底部内容同时避让安全区与键盘；未提交文本在相关页面往返和刷新时保留。

## 验证

NavigationTests 新增 11 项导航回归：重复目标、搜索、项目创建返回、空间编辑返回、创建空间/收藏集、作品归入空间、根页返回、制作空状态、Tab 栈隔离与重选、输入保留、跨 Tab 归档后退出旧项目页面。

首次运行已观察原实现失败，修正后 11 项全部通过。最终回归结果：

- `Test-MadeRoom-2026.09.28_16-39-35-+0800.xcresult`：18 项单元测试（含 11 项导航测试）与 6 条 UI 业务流程全部通过，0 失败。
- `Test-MadeRoom-2026.09.28_16-31-45-+0800.xcresult`：56 个页面逐一检查返回入口与底栏显隐，全部通过，截图导出 56 张。最后的项目流程退出修正不改变页面布局，之后已重新运行业务与导航测试。
- 已实际验证侧滑返回、搜索返回层级、Tab 选中状态、创建/改名空间后的返回、创建项目→完成六步→加入空间→切回制作列表，以及未提交文字的保留。
- 检查设备为 iPhone 17 Pro / iOS 26.1；未在所有 iOS 17–26 真机逐一验证。
